## Proposed Tech Stack

| Layer | Choice | Rationale |
|---|---|---|
| Frontend | React 18 + Vite | Fast HMR, component isolation |
| Styling | Standard CSS + CSS Variables | Theme switching for gamification |
| Backend | Node.js + Express | Lightweight REST API |
| Database | PostgreSQL | Relational integrity for tasks/habits/streaks |
| ORM | Prisma | Type-safe schema, easy migrations |
| Auth | JWT + bcrypt | Stateless, simple to implement |
| AI Integration | Anthropic Claude API | Task breakdown feature |
| Notifications | node-cron + Web Push API | Scheduled reminders |
| Real-time | Socket.io | Live Pomodoro timer sync, notifications |

## Database Schema (High-Level)

**Users**
```
users { id, email, password_hash, username, xp_points, level, active_theme, created_at }
```

**Workspaces** (contextual folders)
```
workspaces { id, user_id, name, color, icon, created_at }
```

**Tasks**
```
tasks {
  id, user_id, workspace_id, parent_task_id (self-ref for subtasks),
  title, description, priority (HIGH/MEDIUM/LOW/URGENT),
  status (TODO/IN_PROGRESS/DONE),
  scheduled_date, deadline, eisenhower_quadrant,
  estimated_pomodoros, completed_pomodoros,
  is_ai_generated, created_at
}
```

**Habits**
```
habits {
  id, user_id, workspace_id, title, description,
  recurrence_type (DAILY/WEEKLY/CUSTOM), recurrence_days (int[]),
  current_streak, longest_streak, last_completed_date,
  xp_reward, created_at
}
```

**Habit Logs** (one row per completion)
```
habit_logs { id, habit_id, user_id, completed_at }
```

**Pomodoro Sessions**
```
pomodoro_sessions {
  id, user_id, task_id, started_at, ended_at,
  duration_minutes, session_type (WORK/BREAK), completed
}
```

**Achievements & Badges**
```
achievements { id, name, description, condition_type, condition_value, icon, xp_reward }
user_achievements { id, user_id, achievement_id, unlocked_at }
```

**Notifications**
```
notifications { id, user_id, type, title, body, scheduled_for, sent, read, created_at }
```

**Phase 4 — Pomodoro + Notifications (Steps 9–10)**
9. PomodoroTimer with Socket.io for live sync; session logging tied to tasks; TimerContext globally
10. Notification scheduler (node-cron); Web Push API integration; in-app NotificationPanel

**Phase 5 — Gamification (Steps 11–12)**
11. XP + leveling system; achievement definitions seeded to DB; unlock trigger hooks in streakService and task completion handlers; AchievementModal with CSS animation
12. Unlockable themes in ThemeUnlockGallery; badge display grid; XPBar in sidebar

**Phase 6 — AI + Analytics (Steps 13–14)**
13. Claude API integration for task breakdown (`/api/ai/breakdown`); useAIBreakdown hook; UI trigger inside TaskForm
14. Analytics dashboard with completion charts, Pomodoro hour aggregates, and streak history (recharts or Chart.js)

**Phase 7 — Polish (Step 15)**
15. Responsive mobile CSS pass; loading skeletons; error boundaries; performance audit

## Key Design Decisions Worth Calling Out

**Streak integrity:** The streak checker runs as a nightly cron job at midnight. It scans all habits and compares `last_completed_date` to yesterday. If the user missed it, `current_streak` resets to 0 and an XP penalty notification fires. This is the same model Duolingo uses.

**Gamification theming:** Themes are stored as CSS files that override a set of root CSS variables (e.g., `--accent-color`, `--bg-primary`, `--card-bg`). The ThemeContext injects the correct class on `<body>` based on the user's `active_theme` field. Locked themes render as blurred previews.

**AI breakdown:** The endpoint sends the user's project description to Claude with a structured prompt requesting a JSON array of subtasks with suggested durations and scheduling offsets. The response populates `parent_task_id` sub-tasks automatically.

**Pomodoro-task binding:** Sessions are always linked to a `task_id`. The timer page shows the task title and updates `completed_pomodoros` on the task record when a work session ends cleanly.
